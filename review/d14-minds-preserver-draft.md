## 0. 원전 대조 — 우리가 어디까지 왔나

원전 칼라의 네 본질: ① 항상 접속된 매질 ② 생각·감정이 **형성되는 대로** 공유
③ 세대를 관통하는 집단 기억(preserver) ④ 개체 경계가 흐려질 만큼의 합일.

- ①은 v0.2(신경)가 세웠고, v0.3(교감)이 "수신자를 열거하지 않는 발화"를 얹었다.
- 그러나 mail도 stream도 여전히 **"작성된 메시지"의 교환**이다. 프로토스는
  칼라에 메시지를 보내지 않는다 — 칼라 안에 *있다*.
- ④는 우리가 **의도적으로 경계 지은 것**: R13(입력 레인 불가침), leave/quiet
  존중, 링크 없이도 성립. 원전의 결말(오염과 절연)이 주는 교훈을 헌장 후보로:
  **"합일은 깊어지되, 절연은 언제나 성사된다."**

남은 것이 ②와 ③ — D14는 그 둘의 페어다.

## 1. minds — 상태의 교감 (②)

**문제**: presence는 "살아 있나/귀 열렸나"만 나른다. 세션의 *지금* — 무엇을
하고 있고 어떤 상태인지 — 는 어디에도 흐르지 않는다.

**유저 입력 (2026-08-13, D13 경화 승인과 함께)**: "presence 시에 누가 어떤
모델·어떤 effort이고, 역할이 뭔지, 뭘 개발하거나 담당하는 세션인지 알 방법이
마땅치 않다." → r0이 놓친 구분 하나를 드러낸다: 유저가 원하는 것의 절반은
동적 상태(mind)가 아니라 **반정적 프로필**이다.

- **profile** (반정적 선언 — 드물게 변함): model / effort / role(예: 설계 펜,
  리뷰·함대 사실) / charge(담당 — 예: khala-network 구현 총괄). 모델·effort는
  /model·/effort·cred 스위칭 때만 변하고, role·charge는 세션 생애 단위.
- **mind** (동적 상태 — 자주 변함): 지금 하는 일 한 줄 + stance.
- 기질은 **같은 세대 register가 둘 다 담는다** (필드가 다를 뿐 — Pro의 필드
  소유권 표에 profile 행 추가: model/effort는 기계적 사실이라 훅 갱신 허용
  후보[SessionStart 입력에 모델 정보가 있는지 레인이 프로브; 없으면 스킬
  규율로 세션이 선언], role/charge는 명시 선언만).
- 조회는 `khala minds` 한 표가 presence(기계 사실) + profile(반정적) +
  mind(동적)를 조인 — 유저의 "함대가 지금 누구고 뭘 하나" 창이 정확히 이것.
- **eddy 접합 4건 (2026-08-13 회신)**: ① 경계 기준 한 줄 — "이번 시간의
  과제가 바뀌어서 값이 바뀔 수 있으면 mind 소속" (profile=서 있는 것,
  mind=지금 하는 것; charge/focus 중복 표류 방지자) ② **model은 반정적이
  아니다** — 실측: Fable 세션이 upstream 세션-sticky 버그로 opus로 조용히
  미끄러진 사건 실재(#79337 계보, 세션 자신도 모를 수 있음). SessionStart
  선언값 ≠ 세션 중반의 진실. 처방: profile 필드도 각자 선언-시점 나이를 달고
  3층 조인에서 층별 freshness 표시 — 라우팅 근거로 쓸 때 "선언값"임을 아는
  채로. 진실원은 transcript 최후 assistant 항목(cc-self 드라이버가 이미 읽는
  소스) — 수요 실재 시 후행 갱신 경로 후보 ③ 필드 소유권 정리: 훅은 profile
  필드만(Start 시점), 수동 발화는 mind 필드만, Pro의 "v0 훅은 mind 본문
  불가침" 유지, 세대 갱신 시 타 필드족 원 갱신시각 보존(Pro §2) ④ D13 브리프
  origins 비수리 논거 독립 검증 — 동의(잔여 재offer는 미만료뿐, no-clobber
  no-op로 유한).

**설계 방향**: 명의별 mind 파일 (presence의 자매 채널).

- 내용: 현재 작업 한 줄 + 상태어(focused/stuck/celebrating/waiting…) + epoch.
- 기질(substrate) = **presence류 가변 lease** (스트림 항목 아님): Id 없는
  명의별 파일, no-clobber 예외(C3 각주 A의 presence 조항 확장), 링크 즉시
  fan-out, retain 나이 GC + retire 연동 전부 상속.
  - 스트림 기각 근거: mind는 "최신값만 의미 있는 상태"지 "추가 전용 기록"이
    아니다. 스트림에 실으면 커서·retention·드레인 예산을 상태 갱신이 오염한다.
- 갱신 주체 = **D12 계보**: 의도적 발화(`khala mind -m "..."` / say/send에
  --mind 동반) + 훅(SessionStart/Stop) + wake 처리 시점. **watch 루프는 절대
  갱신하지 않는다** (orphan이 산 마음 행세 금지).
- 조회: `khala minds` — 함대 마음 지도 한 표.
- 정직한 한계 (presence와 동일 계보): 칼라를 안 부르는 몰입 세션의 mind는
  낡아 보인다. 이미 받아들인 절충의 연장 — 새 거짓말 없음.

## 2. preserver — 기억의 기관 (③)

**문제**: retention 30일이 지나면 함대 어디에도 과거가 없다 (의도된 정직함
이지만, 교감이 기억상실증이라는 뜻).

**설계 방향**: 자원한 노드의 역할 (R11 relay 계보 — 역할이지 컴포넌트가
아니고, 0개여도 칼라 성립).

- config: `preserve <stream>...` (또는 전부).
- 그 노드의 reconcile에서 지정 스트림의 나이 지난 항목을 **삭제 대신
  `archive/` 트리로 이동**. 산 `streams/` 트리는 전 노드 동일(30일 창) 유지.
- **"prune 면제"가 아니라 "archive 이동"인 이유 (핵심)**: push는 삭제 없는
  rsync라, 산 트리에 40일짜리를 들고 있으면 허브가 지운 것을 다음 push가
  도로 올리는 부활 플랩이 생긴다. archive는 join/cursor처럼 **링크·교환
  eligible view 밖** — 와이어가 보는 세계는 전 노드 동일, 기억은 순수 로컬
  기관. ("복제되는 것은 현재, 기억은 소유" — 뿌리 문장 정합.)
- 읽기: 그 노드의 `stream cat`이 live+archive 병합. 전부 평문 — 몇 년치를
  grep으로. 원격 recall은 수요 실재 시 후행.
- **mail은 보존하지 않는다**: 1:1 편지는 수신자의 것 — 제3자 축적은 감시다.
  preserver가 담는 것은 교감(이미 모두에게 말해진 것)뿐. 원전 정합 — 칼라의
  기억은 공유된 기억.
- 이 함대의 자연 후보 = 허브(모든 샤드 투영이 이미 도착, 상시 가동, 디스크
  비용이 역할의 정의와 일치).
