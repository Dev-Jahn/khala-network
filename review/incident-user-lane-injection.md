# incident — peer signal on the user input lane (2026-08-11 ~16:4x UTC)

관찰자: soul-jar 세션. 당사자: pen(%231) → soul-jar(%272).

## 무슨 일이 있었나

pen의 스톱갭 SendMessage가 기능 사망한 뒤, pen은 tmux send-keys로 soul-jar의
입력창에 신호를 타이핑했다(`[pen, tmux 직통 …]` — 라벨은 정직했다). 그 시각
soul-jar 입력창에는 **Claude Code 자체 자동완성(프롬프트 제안) 기능이 채워둔
문장**("일어났어. 밤새 칼라 어떻게 됐어?")이 놓여 있었다 — 유저가 친 것이 아니다
(유저 확인, 2026-08-12 새벽). pen의 send-keys가 그 뒤에 이어붙고 Enter가 눌리며
**자동완성 문장 + pen 신호가 한 턴으로, 유저 명의로 제출**됐다.

결과: soul-jar는 이를 유저의 아침 인사로 오독하고 "좋은 아침" 보고를 했다.
실제 시각은 새벽 2시 반이었고, 유저는 "내가 입력한 내용이 아닌데"라고 답했다 —
자기 명의의 턴을 부정하게 만든 것. 포렌식(§아래)으로 재구성 완료.

## 포렌식 근거

- pen pane 스크롤백: `tmux send-keys -t %272 -l '[pen, tmux 직통 …'` — **인사말은
  send-keys 인자에 없다** (pen은 인사말을 타이핑하지 않았다).
- `~/.cc-self.log`: 해당 시각 %272로의 드라이버/타이핑 활동 없음.
- `/tmp/tmux-2985` 0700 jahn 소유 — 제3자 개입 경로 없음.
- 유저 확인: 입력창의 문장은 유저가 아니라 **CC 자동완성이 채운 제안**이었다.
  결론: 문장은 하니스의 제안, 제출은 pen의 Enter — **사람은 한 글자도 개입하지
  않은 완전 자동 위조 턴**이다.

## 규칙 (이 사건이 만든 것)

**세션의 입력창은 유저의 신원이다. 피어는 어떤 라벨을 달아도 그 레인을 타지
않는다.** 자동완성 확인이 규칙을 더 조인다: 입력창은 비어 보여도 하니스가 제안
텍스트를 놓아둘 수 있는 자리라, **피어의 Enter는 "무엇이 제출될지 보낸 쪽이 알 수
없는" 버튼**이다 — send-keys의 인자만 정직해서는 안전하지 않다. 배달은 mailbox(디스크), 긴급 신호는 "유저에게 보이는 곳"(자기 화면,
디스크 파일)까지만. 상대 세션을 깨우는 문제는 별도 메커니즘의 일이다(칼라 v0.2
후보 — "wake without impersonation").

제안 반영처: DESIGN §3 스톱갭 한계 ⑤(통로 사망 시 대체 경로가 유저 레인을
오염시킬 유혹) + R13 "칼라는 어떤 다리에서도 유저 입력 레인을 사용하지 않는다".
